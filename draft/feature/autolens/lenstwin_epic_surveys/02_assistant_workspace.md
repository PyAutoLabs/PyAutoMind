## §1 autolens_assistant architecture

- `AA/AGENTS.md` is the canonical, agent-agnostic constitution; `AA/README.md` the user front door; `AA/llms.txt` the router (read order: AGENTS.md → skills/README.md → skill → wiki). No CLAUDE.md or REFERENCE.md at the root.
- Three-layer model: instructions → skills (procedural, "how do I X") → wiki (content, "what/which/why X"). End-to-end work composes skills and cites wiki pages.
- **A skill is one flat Markdown file `skills/<name>.md`** (`AA/skills/_style.md`), not a directory. Frontmatter `name:` and `description:` (when to use, when not), optionally `user-invocable: true`. Naming: `al_<task>.md` for lensing-API skills; kebab-case for project workflows (`start-new-project.md`, `init-slam.md`, `contribute-upstream.md`); `euclid_<task>.md` for Euclid mode; `_style.md`, `_bootstrap_skill.md` are meta-skills. Body arc Orient → Ask → Branch → Combine; each Branch has physics framing, a full runnable Python recipe, a wiki link plus a `<Project>:<path>` citation. Every `al_*` skill ends with `## Further reading` generated from `AA/wiki/core/external/skill_citation_map.md`.
- **Python-first:** the deliverable is a user-specific `.py` in `scripts/`; "do not just point the user at a pre-existing script in another repo… cite it but produce the user-specific script regardless." Generated scripts use the workspace style (title underlined with `=`, `__Contents__`, `"""__Section__"""` docstrings) and convert to notebooks via `autoassistant/to_notebook.py`.
- Harness adapters: `AA/.claude/skills/*` and `.claude/commands/*` are symlinks to `../../skills/*.md`; Codex uses generated `.codex/skills/autolens-assistant-<skill>/SKILL.md`; both regenerated with `bash ${PYAUTO_BRAIN}/bin/install.sh --write-project-discovery autolens_assistant`. Code gate: hook `.claude/hooks/validate_pyauto_code.py` plus `autoassistant/audit_skill_apis.py` blocks PyAuto symbols that cannot be resolved.
- Workspace relationship: cited as `autolens_workspace:scripts/...`; `AA/sources.yaml` gives it role `tutorial-scripts`, read-only, no pin. AA never vendors the workspace: installed copy → sibling clone → clone-on-demand into gitignored `sources/`; then read its `llms.txt` / `llms-full.txt` / `workspace_index.json`, never `llms-full.txt` whole. Only stack pin: `AA/version.txt` (2026.7.9.1) plus `wiki/core/api_audit_baseline.json`.
- Wiki (`AA/wiki/README.md`): `core/` (read-only curated PyAuto reference: `stack/`, `concepts/`, `api/`, `operations/`, `external/`; frontmatter `title`, `sources` with `pinned_commit`, `last_updated`; new pages link from `core/index.md` and the citing skills), `literature/` (concept/entity/source pages with `[[wiki-link]]`; includes `concepts/bulge-halo-decomposition.md`, `sources/bulge-halo.md`), `euclid/`, `project/` (per-clone `state.md`, `profile.md`, journal; templates `_template.md`, `_state_template.md`, `_results_summary_template.md`, `_profile_template.md`).
- No capability matrix or workflow registry. Closest: the index in `AA/skills/README.md`, `skill_citation_map.md`, the empty "Example projects (registry)" section of `start-new-project.md`, `AA/colab/contexts.yaml`.

## §3 Adding a capability

`_bootstrap_skill.md` protocol: confirm scope (one task per skill) → read `_style.md` → resolve source repos via `sources.yaml` → read the real API, never guess → draft or link wiki pages (frontmatter `sources` + `pinned_commit`) → write `skills/al_<task>.md` → regenerate the Claude and Codex adapters and add a line to `skills/README.md` → verify by writing and running the script with `PYAUTO_TEST_MODE=1` ("don't ship a skill whose recipe doesn't execute"). Do not bootstrap when the request is a small variant of an existing skill (extend it) or is "run this existing tutorial script" (point at it). Adding a skill also needs a row in `skill_citation_map.md`. No explicit rule that a skill must point at a tested workspace script; the practice is the Further-reading workspace column plus workspace CI smoke tests.

Evaluation: `AA/benchmarks/` holds frozen one-shot prompt cards (`prompts/oneshot/<id>/card.md` + `score.py`), hidden truth in `benchmarks/truth/`, runs in `benchmarks/runs/<id>/<date>_<model>_<harness>/`, runner `autoassistant/benchmark.py`, `VERSIONS.lock` freezes prompts by hash. Existing cards: `cosmos-web-ring-fit`, `positions_initialised_inference` (simulated dataset + `make_truth.py`), `forward_model_consistency`, `oneshot-smoke`. PyAutoBroca is mentioned once (`al_refresh_colab_contexts.md:213`); no Broca eval requirement for skills. `AA/modes/maintainer.md` lists generic vs PyAutoLens-specific content.

  lp_chain_tracer = al.util.chaining.lp_chain_tracer_from(light_result=..., settings_search=...)
