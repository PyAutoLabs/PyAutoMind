## Why

Second of the two one-shot, machine-scored assistant benchmarks (design 2026-09-17;
harness and score contract in `oneshot_benchmark_harness.md`, which this card is
**blocked on**). No inference: the difficulty comes from chaining three workspace
packages (`imaging`, `point_source`, `interferometer`) plus data preparation so every
stage depends on the previous one being right, and from a scorer that mostly rewards
**agreement between packages**, which a wrong unit, sign or (y,x) convention breaks in
several rows at once. Compute is well under a minute; the five minutes are the agent's.

## The card

**Prompt** (frozen by hash; final wording written with the card) gives a *physical*
specification, not library parameters: lens and source redshifts; an EPL with a stated
Einstein radius in arcsec and slope 2.2; external shear as magnitude and position
angle; a Sersic source with an AB magnitude and a zero point, effective radius, index;
a PSF as a FWHM in arcsec; pixel scale, image size, exposure time, background sky,
random seed; the uv-wavelengths file to use for the interferometer. Then one ask:
build this lens so the source is **quadruply imaged**, and produce the imaging, the
point-source dataset and the interferometer dataset it implies, with a report showing
they agree with each other.

The agent must:
1. convert the spec to profile parameters (Einstein radius → EPL normalisation,
   magnitude → intensity, FWHM → sigma in pixels) — each conversion is exactly visible
   to the scorer;
2. choose a source centre inside the tangential caustic so the multiplicity is four —
   the scorer computes the multiplicity itself, a double scores 0 on that row;
3. simulate the imaging dataset and write `image.fits`, `noise_map.fits`, `psf.fits`;
4. solve the image-plane positions of the source centre with the point solver, write
   positions, magnifications and **time delays in days** as a point dataset (forces a
   cosmology, redshifts and units);
5. simulate the interferometer visibilities of the same tracer with the given uv
   wavelengths and write a dirty image;
6. derive an imaging mask from the solved positions with the data-preparation
   tooling, containing all four images and excluding the lens centre;
7. write `result.json` with every derived number and file path, and one consistency
   figure: imaging with positions and critical curves overlaid, dirty image beside it.

**Gates**: harness-inherited plus — every file loads through the library's own readers
(`Imaging.from_fits`, `PointDataset.from_json`/`from_dict`, `Interferometer.from_fits`
or the current equivalents; verified at authoring time against the released wheel).

**Metrics** (each in [0,1], mappings frozen in `score.py`; cross-package rows weigh 2×):
- image, noise map, PSF vs the reference simulation (normalised max abs difference);
- multiplicity == 4; positions match the reference set after optimal pairing to within
  one pixel; magnifications and time delays within stated relative tolerances;
- **cross-package**: each solved position sits on a local maximum of the simulated
  image; dirty-image peaks land at the same positions after the uv gridding;
- the mask contains all four positions and excludes the centre;
- the model the agent saved (read back) has the specified Einstein radius, slope,
  shear and source magnitude within tolerance;
- consistency figure exists and is a real PNG.

**Truth** (hidden, `benchmarks/truth/<card>/`): the reference simulation, positions,
magnifications, time delays and multiplicity, regenerated by `make_truth.py` from the
spec with the fixed seed and a recorded library version. Deterministic: two runs of
`make_truth.py` on the same wheel produce byte-identical FITS.

**Version 2 (not this task, note in the card)**: a group-scale variant with a second
lens galaxy pulls in the `group` package and makes the caustic reasoning non-trivial;
hold until the single-lens card has calibrated scores.

## Do

Author the card (`benchmarks/prompts/oneshot/forward_model_consistency.md`), its
`score.py`, `make_truth.py`, truth artefacts and tests (schema, mappings, the pairing
routine, a synthetic `result.json` scoring end to end, and a test that a (y,x)-swapped
positions set fails the cross-package rows). Then run it three times on a laptop with
Claude Code and the current default model, commit the runs, regenerate `RESULTS.md`, and
write the calibration note in the card: which rows discriminated, which saturated,
whether any stage was under-specified in the prompt (fix by `version` bump, never by
editing the frozen prompt in place).
