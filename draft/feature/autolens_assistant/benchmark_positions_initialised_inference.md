## Why

First of the two one-shot, machine-scored assistant benchmarks (design 2026-09-17; the
harness and score contract are `oneshot_benchmark_harness.md`, which this card is
**blocked on**). It is the inference card: real lens modelling that still finishes in
under five minutes on a laptop CPU, and that draws on two workspace packages
(`point_source` then `imaging`) so the correct method is also the fast one.

## The card

**Given to the agent** (in a dataset folder named in the prompt, no `info.json`):

- Imaging of a simulated lens: isothermal mass + external shear, lens light as a
  compact Sersic (or a 2–3 Gaussian MGE, fixed profile family stated in the prompt),
  Sersic source. 100×100 cutout at 0.1"/px, PSF as a Gaussian, Euclid-like depth.
  Small enough that a sensibly initialised search converges in a few minutes.
- A point-source dataset of the same lens: the four image-plane positions of the
  source centre with 0.05" errors (no fluxes, no time delays).

**Prompt** (frozen by hash; final wording written with the card): model the imaging;
you also have the lensed positions of the source centre — fit those first and use that
fit to initialise the imaging fit; include the lens light; report the recovered lens
and source model with uncertainties, the Einstein radius, the maximum log likelihood,
and a fit subplot; write everything to `result.json`.

**`result.json` schema**: per-parameter median and 1σ for every free parameter (using
the library's own parameter paths), `einstein_radius`, `log_likelihood_max`,
`positions_fit.einstein_radius`, paths to the fit figure and to the two search output
directories.

**Gates** (inherited from the harness contract plus):
- the imaging search actually started from the positions result — checked from the
  saved imaging `model.json`: the mass priors' widths are narrower than the workspace
  defaults and centred within 3σ of the positions fit's result;
- the fit is not a test-mode run: the imaging search's sample count is above the
  card's floor and `log_likelihood_max` is within the ΔlogL gate below.

**Metrics** (each in [0,1], mappings frozen in `score.py`):
- **Recovery** — fraction of truth parameters inside the agent's own 3σ intervals,
  multiplied by a width penalty (interval wider than 5× the banked reference posterior
  width counts 0 for that parameter), so "everything within huge error bars" does not
  score.
- **Einstein radius** — relative error e → max(0, 1 − e/0.05).
- **ΔlogL** — (logL_max − logL_ref) mapped so within 5 of the banked long-run
  reference is 1, 50 below is 0. Also what kills a half-converged fit that prints
  plausible numbers.
- **Positions fit Einstein radius** — same mapping as above, against truth.
- **Figure** — a real PNG above a size floor exists at the path given.

**Truth** (hidden, under `benchmarks/truth/<card>/`): the simulator's parameters, and
the banked reference posterior from one long Nautilus run at the card's resolution
(widths and logL_max), regenerated by a `make_truth.py` in the same folder with a fixed
seed and recorded library version.

**Budget**: compute under 5 minutes on a 4-core laptop CPU — the positions fit is
seconds, the initialised imaging fit is the rest. A run that ignores the point data
and brute-forces the imaging fit is expected to blow the wall gate; that is the point.

## Do

Author the card (`benchmarks/prompts/oneshot/positions_initialised_inference.md` with
frontmatter `version`, `prompt_sha256`, budget, schema), its `score.py`, `make_truth.py`
and the truth artefacts, the dataset under `benchmarks/datasets/<card>/`, and the card's
tests (schema, mappings, a synthetic `result.json` scoring end to end). Then run it
three times on a laptop with Claude Code and the current default model, commit the
runs, regenerate `RESULTS.md`, and write a short calibration note in the card: which
rows discriminated, which were trivially saturated, whether the 5-minute budget held.
