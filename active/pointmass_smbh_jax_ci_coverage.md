## Original request (verbatim)

> ok yes do a CI exercise in autolens_workspace_test with JAX on these profiles
> as a quick follow up

Follow-up to PyAutoGalaxy#553 / PR#554 (merged daf3b8d8): `al.mp.PointMass` and
`al.mp.SMBH` broke every JAX fit and nothing in CI exercised the JAX path for
point-mass profiles, so the regression class was invisible.

## Plan

Two touches in @autolens_workspace_test, covering both bug shapes:

1. `scripts/misc/profiles_jit.py` — add `mp.PointMass` and `mp.SMBH` to the
   mass-profile list (`deflections_yx_2d_from`, `convergence_2d_from` on both
   `Grid2DIrregular` and `Grid2D.uniform`, three-step JAX pattern). Catches the
   ArrayIrregular/deflections bug shape at the profile level. Runs in the full
   sweep / release profile (not in smoke_tests.txt).
2. New `scripts/imaging/jax_likelihood/smbh.py` — full-pipeline vmap+jit
   likelihood with lens = Isothermal + `SMBH` where `mass` is a FREE parameter
   (LogUniformPrior; redshifts fixed floats). A free traced mass is the ONLY
   way to catch the `SMBH.__init__` traced-`np.sqrt` bug shape —
   `profiles_jit.py` instantiates with floats and can never see it. Mirror
   `imaging/jax_likelihood/lp.py` exactly (auto-sim `jax_test` dataset,
   `__Env__` with `ENV: jax full_datasets`, hardcoded vmap literal generated by
   running the script, Path A jit round-trip vs numpy). Add to
   `smoke_tests.txt` so the PR CI gate runs it (300s cap; lp.py-scale cost).
3. Update `scripts/CLAUDE.md` (jax_likelihood table row + profiles_jit list).

Traps: run `lp.py` first as a CONTROL to confirm the local env reproduces its
pinned literal before generating ours; wipe `output/` between runs; the vmap
literal must be generated under the same env tokens CI applies.
