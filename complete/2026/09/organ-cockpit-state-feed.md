Type: feature

Issue: https://github.com/PyAutoLabs/PyAutoBrain/issues/416
Epic: organ-cockpit

Every organ dashboard is a static Pages HTML page regenerated by a daily cron. The human manages the ecosystem from those pages as a pile of browser tabs, and nothing directs attention to a RED Heart. Phase 1 of the organ cockpit adds the two layers everything later builds on, without moving truth off GitHub. This prompt covers the Brain and the Heart only; the other organs adopt the feed in follow-up prompts once the schema exists.

1. A fixed state.json schema (organ, status colour, updated stamp, one-line headline, attention items each with a GitHub link) plus a validator, living in PyAutoBrain. The Brain board workflow (brain_board.yml) emits state.json next to its Pages board as the reference implementation, and the Heart board workflow (heart-health.yml) emits its own from the readiness verdict.
2. A transition-only push alert on the PyAutoHeart board workflow: compare the new readiness verdict with the previous state and, only on a change such as GREEN to RED, POST to an ntfy or Pushover topic held in a repo secret.

Out of scope (later phases): the remaining organs emitting the feed (one small prompt each), the PWA cockpit page on pyautolabs.github.io reading all feeds with Heart pinned first, the start_dev Heart-RED gate, a tray-dot script, the Claude Code status line. No server, no Electron, no browser-side GitHub API reads.

Witness: PyAutoBrain ships schema/state_schema.json and a validator with a test over fixture feeds for Brain and Heart; the two board workflows publish state.json (curl of the Pages URL returns JSON that passes the validator after the next deploy); the Heart alert step is exercised by a unit test that feeds GREEN->RED and GREEN->GREEN state pairs and asserts one POST and zero POSTs respectively.
