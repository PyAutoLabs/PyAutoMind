Merged PyAutoBrain#738 (human /prm, 2026-11-27). This is the code for Phase 14.3 of the maintenance orchestrator.

`batch brief --new <slot> --maintenance --out <record> --mind <linked-worktree Mind> [--home …]` reads the boards through the 14.1 adapters and files findings through the 14.2 writer. It obeys the read flags and ranks findings glance-first (tier, then priority, then source, then input order, under one cap). It then names generated prompts (`Source-key:`) as the shift's tasks, skipping any that are claimed, blocked, done, no longer listed, outside the tier filter or past the cap.

The brief it writes has:
- a `maintenance:` block;
- `backlog: none`;
- lanes `any local-dev`;
- `merge-cap: 0`;
- a digest line that names it as a maintenance shift.

The M3 gate is enforced on the tasks, so a live maintenance shift can't start before the M3 grant:
- shadow is the default, and a shadow brief spawns no workers;
- `--live` needs `--gate-open`, which writes `gate-open: PyAutoBrain#574`;
- `brief --check` refuses a non-shadow brief that has generated tasks or `sources: maintenance` but no gate line;
- `scope()` keeps generated prompts out of every dip that lacks the gate (named, resumed and added tasks alike);
- `/add` of a generated prompt is refused without the gate.

The real `maintain.json` is written only with an explicit `--home`. A real launch passes `"$PYAUTO_ORCHESTRATOR_HOME"`.
