## Why it is there

`.gitignore` states the governing rule itself (lines 27-36):

    # Auto-simulated input datasets — regenerated by profiler scripts, not committed.
    # These regenerate BYTE-IDENTICAL to the removed committed copies (verified per
    # instrument: imaging euclid/jwst/ao, interferometer sma) via
    # _profile_cli.auto_simulate_if_missing -> scripts/misc/simulators/<type>.py.
    # Datasets that do NOT regenerate byte-identically remain tracked and are NOT
    # covered by these rules: imaging/hst (stale re-mirror), imaging/source_complex
    # (no producing simulator), ...

So: byte-identical regeneration → ignored; otherwise → tracked. `jwst_lw` is
registered in `instruments/imaging.py:56` with a deterministic `seed: 1`, on the
same `auto_simulate_if_missing` path as `jwst`, `euclid` and `ao` — all three of
which are ignored. Its own sibling `dataset/imaging/jwst/` is ignored at line 43.
`jwst_lw` was added later as the long-wavelength counterpart (0.06 vs 0.03
arcsec/px, for the heterogeneous multi-band datacube A/B in
`scripts/misc/searches/_setup.py:103`) and the `.gitignore` was never extended.

## The work

1. **Control-test the premise first.** The gitignore comment lists euclid/jwst/ao
   as *verified* byte-identical — **not** `jwst_lw`. Do not inherit that claim.
   Move the directory aside, re-run the auto-simulate path, and compare the
   regenerated files byte-for-byte against the copy that was moved. Only if they
   match does `jwst_lw` belong in the ignored class.
2. If it regenerates byte-identically: add `dataset/imaging/jwst_lw/` alongside
   its siblings, and delete the working copy (it costs one re-simulate).
3. If it does **not**: it belongs in the tracked class with `hst` and
   `source_complex` — commit it and extend the comment's "do NOT regenerate"
   list with the reason, so the next reader does not re-derive this.

Either way the outcome is the same headline: `autolens_profiling` stops showing
as a dirty checkout for a reason that is really a bookkeeping gap.
